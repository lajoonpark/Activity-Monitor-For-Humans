# Plan: Ship MacExplainer as a standalone DMG

## Goal

Let anyone download `MacExplainer` as a `.dmg` from the GitHub repo and run it
as a standalone app: one script produces a drag-to-Applications DMG locally,
and the same script runs in GitHub Actions on each version tag to attach the
DMG (plus checksum) to a GitHub Release.

## Decisions (confirmed with user)

- **No Apple Developer account** → no Developer ID signing / notarization.
  Distribution is **ad-hoc signed**; Gatekeeper will show the standard "developer
  cannot be verified" warning, which is documented as the expected workaround.
- **CI + local script**: a single `scripts/make_release.sh` used both locally and
  by a tag-triggered GitHub Actions workflow. Actions must be enabled on the repo.
- **Mixed architecture**: produce an arm64 + x86_64 universal app so the DMG runs
  on both Apple Silicon and Intel Macs (no third-party deps, so this is cheap).

## Current state (verified)

- Project: `MacExplainer.xcodeproj`, target `MacExplainer`, scheme `MacExplainer`,
  deployment target macOS 14.0, `PRODUCT_BUNDLE_IDENTIFIER = com.macexplainer.app`,
  `MARKETING_VERSION = 1.0`, `CURRENT_PROJECT_VERSION = 1`.
- Signing today: `CODE_SIGN_IDENTITY = "-"` (ad-hoc), `CODE_SIGN_STYLE = Automatic`,
  `ENABLE_HARDENED_RUNTIME = YES`, sandbox disabled (`MacExplainer.entitlements`).
- `GENERATE_INFOPLIST_FILE = YES`; icon exists in
  `MacExplainer/Resources/Assets.xcassets/AppIcon.appiconset/AppIcon.png`.
- Local build output currently lands in `.build/Build/Products/<Config>/MacExplainer.app`.
- Remote: `github.com/lajoonpark/Activity-Monitor-For-Humans`.
- Repo hygiene gaps: no root `.gitignore`; `.build/` and `default.profraw` are
  untracked but pollute the tree; `*.xcuserstate` is **tracked** in git.

## Task 1 — Repo hygiene

1. Add root `.gitignore`:
   - `.build/`
   - `default.profraw`
   - `dist/`
   - `*.dmg`
   - `xcuserdata/`, `*.xcuserstate`
2. `git rm --cached` the tracked
   `MacExplainer.xcodeproj/project.xcworkspace/xcuserdata/.../UserInterfaceState.xcuserstate`
   (keep file on disk) so GitHub zips are clean.
3. Commit; verify `git status` no longer shows build junk.

## Task 2 — `scripts/make_release.sh` (single source of truth)

Behavior (bash, `set -euo pipefail`):

1. Resolve repo root from script location; allow `OUT_DIR` override (default
   `dist/`); `mkdir -p`.
2. Read `MARKETING_VERSION` from the project (via `xcodebuild -showBuildSettings`
   or grep of `project.pbxproj`) → used in the DMG filename.
3. Build Release universal:
   `xcodebuild -project MacExplainer.xcodeproj -scheme MacExplainer
   -configuration Release -destination 'platform=macOS'
   -derivedDataPath .build ARCHS='arm64 x86_64' ONLY_ACTIVE_ARCH=NO build`
4. Locate `.build/Build/Products/Release/MacExplainer.app`.
5. Re-sign explicitly ad-hoc + hardened runtime:
   `codesign --force --sign - --options runtime` on the bundle (and verify
   `codesign --verify --deep --strict`).
6. Stage DMG contents in a temp dir:
   - `MacExplainer.app`
   - symlink `Applications` → `/Applications`
   - `README.txt` (drag the app to Applications; Gatekeeper workaround note)
7. Create DMG:
   `hdiutil create -volname MacExplainer -srcfolder <staging> -ov -format UDZO
   "$OUT_DIR/MacExplainer-$VERSION-macOS.dmg"`
8. Emit `shasum -a 256` next to the DMG as a `.dmg.sha256` file; print final paths.
9. Idempotent: wiping temp staging each run.

Notes for the implementer:
- Keep no signing-identity branching (decision = ad-hoc only), but structure the
  sign step so a future Developer ID path is a one-line change.
- `spctl --assess` will legitimately fail (no Developer ID) — do NOT gate on it;
  print a human note instead.
- Universal build is slower; acceptable.

## Task 3 — `.github/workflows/release.yml`

- Trigger: `push` of tags matching `v*`, plus `workflow_dispatch` (version input
  optional for manual test runs).
- Job on `macos-14` runner:
  1. `actions/checkout`
  2. `./scripts/make_release.sh`
  3. Determine the generated filename/tag.
  4. `gh release create` the tag release (if missing) and
     `gh release upload` the `.dmg` + `.sha256` (uses preinstalled `gh`,
     `GITHUB_TOKEN` default — no third-party actions).
- Note: the Release/Core scheme is auto-generated by Xcode; add a step
  `xcodebuild -list` sanity check, and if headless builds fail to find the
  scheme, commit a **shared Scheme** card under
  `MacExplainer.xcodeproj/xcshareddata/xcschemes/`.
- Only attach the DMG artifact to `dist/`-equivalent; do not commit it.

## Task 4 — README.md updates

- New **"Download / install"** section near the top: get the DMG from the
  GitHub **Releases** page, drag `MacExplainer.app` to Applications.
- **Gatekeeper note**: the app is ad-hoc signed (no paid Apple Developer ID), so
  the first launch may say the developer can't be verified. Workarounds:
  Control-click the app → Open → Open; or System Settings → Privacy & Security →

- New **"Building a release"** section: `./scripts/make_release.sh` locally for a
  test DMG; push a `vX.Y.Z` tag to attach the DMG to a Release via CI.
- Update **"Repository map"** and **"Build and run"** to mention the script,
  `.github/workflows/release.yml`, and `dist/`.
- Keep requirements/other sections accurate.

## Validation

1. `xcodebuild test -scheme MacExplainer -destination 'platform=macOS'` still
   passes (unchanged behavior).
2. Local: `./scripts/make_release.sh` → confirm in `dist/`:
   - DMG mounts and shows app + Applications symlink.
   - `codesign --verify --deep --strict MacExplainer.app` passes.
   - App launches after drag-install / to `/Applications`.
   - `shasum -a 256` file matches `shutil` checksum.
3. CI: push a test tag (e.g. `v0.9.9-test`) or use `workflow_dispatch`; confirm
   the DMG and checksum appear on the Release and download on a clean Mac works
   through the documented workaround.
4. Confirm `git status` is clean of `.build/`, `dist/`, `default.profraw`.

## Risks / out of scope

- **Not notarized** (decision): downloads keep the Gatekeeper warning; documented.
  Future option: add Developer ID cert + `notarytool`/`stapler` into
  `make_release.sh` when a paid account exists.
- **GitHub Actions quota**: ad-hoc universal builds on `macos-14` use paid-minted
  runner minutes; fine for occasional releases.
- **Auto-update (Sparkle)**: out of scope — no signing/notarization; a future
  notarization step would be its natural precondition.
- **DMG visual background**: out of scope; plain, functional drag-to-Applications
  DMG (custom artwork can be layered on later without touching the script logic).
- Quarantine xattr set by browsers/Downloads on the DMG is what triggers the
  warning; the README workaround covers it.
